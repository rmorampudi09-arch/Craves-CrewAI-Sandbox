# Delivery Intelligence Migration Incident and Fix — 14 July 2026

## Incident

The first deployment of Delivery Intelligence V1 built successfully but the new Integration Service revision failed during Flyway migration `V2__delivery_intelligence_foundation.sql`.

Azure Database for PostgreSQL returned SQL state `0A000` because `pgcrypto` was not present in the server's `azure.extensions` allow list. The failing statement was:

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;
```

Flyway reported that the migration transaction was rolled back. The previous healthy Container App revision continued serving traffic.

## Engineering decision

No Azure PostgreSQL extension allow-list change was made. `pgcrypto` is not required by the Delivery Intelligence implementation because UUID values are generated by the Java service before inserts.

The V2 migration was changed to:

- Remove `CREATE EXTENSION IF NOT EXISTS pgcrypto`.
- Remove database-side `DEFAULT gen_random_uuid()` expressions.
- Require the Java service to provide UUID primary keys explicitly.

This keeps the migration extension-free and avoids granting unnecessary database capabilities.

## Why modifying V2 was safe

The migration failed transactionally and Azure PostgreSQL rolled back its changes. There was no successful V2 Flyway history entry to preserve, so correcting the un-applied migration file was the appropriate recovery.
